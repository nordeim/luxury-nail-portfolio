# AGENTS.md — HomeNest Kitchen

Production e-commerce storefront + admin console: Vite 7 · React 19 · TypeScript strict · Tailwind CSS 4 (CSS-first) · Vitest + Playwright, built to a single HTML file via `vite-plugin-singlefile`.

## Environment & database contract

- `.env` pins `DATABASE_URL="file:../db/custom.db"`. `db/` sits at the **repo root** and is git-ignored.
- The URL is **schema-relative** (resolves the way the Prisma CLI would: against a `prisma/` anchor), so `file:../db/custom.db` lands in `<repoRoot>/db/custom.db` regardless of CWD. The resolution rules live in `src/lib/db-path.ts` and are pinned by `tests/db-path.test.ts` — do not simplify them.
- The SPA itself never opens the SQLite file: all state lives in `localStorage` under the key `homenest.v4` (bumped with the seed each time the persisted shape or catalog changes — the pairing is enforced by `tests/catalog-hash.test.ts`). The env contract exists for tooling parity with the reference architecture and for the admin Settings surface.
- `npm run db:setup` (session 26, R26-03) materializes the contract as a REAL SQLite `db/custom.db` — schema + catalog + demo-user digests, idempotent, zero dependencies (`node:sqlite`, Node ≥ 22.5). Tooling parity only: ADR-001 still holds, Prisma stays rejected, and a shell-level `DATABASE_URL` overrides the repo default (unset it if the file lands outside the repo root).

## Architecture rules

1. **Dependencies point downward only** — `pages/ → components/ → lib/ → data/`. `lib/` must not import from `pages/` or `components/`. There is no backend; `lib/store.tsx` is the single state seam.
2. **One `StoreProvider`** (`src/lib/store.tsx`) owns products, cart, wishlist, orders, users, promo, toasts, overlay flags. Mutations flow through its callbacks only. Persisted state re-hydrates from localStorage in a mount effect; the `ready` flag exists so role/session gates don't fire early.
3. **Gate on `ready` before navigating away.** `AdminFrame` and `AccountPage` wait for `ready` before redirecting unauthenticated visitors. On a hard refresh the session hydrates after mount — navigating on first render kicks logged-in users out (this was a real bug; don't reintroduce it).
4. **Router is a custom history-API router** (`src/lib/router.tsx`). Route matching is centralized in `matchPath`; new routes need (a) a `matchPath` entry, (b) an `App.tsx` switch case, (c) guards if privileged. Product pages respond to BOTH `/product/:id` (reference URL shape) and `/products/:slug` (slug deep links).
5. **Money is integer cents everywhere.** Formatting happens at display time via `formatMoney`. Shipping/tax/promo math lives in `lib/commerce.ts` and is unit-pinned.
6. **Totals are always re-derived, never trusted from a caller.** `cartTotals(lines, products, code)` is the single source of truth for subtotal → discount → shipping → total.
7. **Cart mutations are delta-based with stock clamps** (`mergeCartLine`, `clampQuantity`) — no absolute-quantity writes, so rapid stepper clicks cannot lose updates.
8. **Deliberate divergences from the reference site are registered** in `Project_Architecture_Document.md` §5.6. Do not "fix" them: promo codes (collapsed in cart), card payment option (second radio), wishlist, admin console, delivery-window estimates, chat FAB → `/contact`, 24-product catalog.
9. **Passwords are never stored as plaintext.** `User.passwordHash` holds `s1$<salt>$<sha256(salt:password)>` (`src/lib/password.ts`, WebCrypto + CSPRNG salt). `login`/`register`/`changePassword` are async; `verifyPassword` still accepts legacy plaintext records and upgrade-on-login re-hashes them. The demo seed ships pre-hashed (static salts — a static seed cannot carry random ones); do not revert it to plaintext, and never log or dump passwords. SHA-256 is not a KDF — the server-backed workstream (PAD §6.3) remains the real fix.
10. **The route-head contract has one seam.** `src/lib/seo.ts` (`buildRouteMeta`) owns titles, canonical, og:url, and the Product JSON-LD shape; `src/components/head-manager.tsx` only APPLIES it inside `RouterProvider`. New routes need a title there (or an entry in the static map) — never set `document.title` ad hoc in a page. The per-route title map mirrors the reference's inline map (incl. "Order Tracking" / "Terms Of Service" quirks); admin titles drop its `admin/` artifact; PDPs get `{Product} | HomeNest Kitchen` (registered divergences, PAD §5.6 #15).
11. **SEO artifacts are generated, never hand-edited.** `public/robots.txt` + `public/sitemap.xml` come from `scripts/generate-sitemap.mjs` (runs via the `prebuild` hook). `tests/sitemap.test.ts` gates the committed artifacts against the catalog — a catalog edit that changes visible slugs requires re-running the generator, and the origin must stay in sync with `VITE_SITE_URL` (see `.env.example`).

## Tailwind v4 trap log (violations here silently break visual parity)

All tokens live in `src/index.css` under `@theme`. Measured against the reference site (nest-culinary-hub.base44.app) on 2026-10-12.

1. Theme colors are full `hsl(...)` literals — bare `H S% L%` triplets resolve transparent.
2. `--shadow-sm` is pinned to v3 geometry; v4 shifted the scale one notch.
3. Hero/category overlays use explicit `linear-gradient(...)`, not `bg-gradient-to-*` (v4 interpolates in oklab).
4. `space-y-*` is inert on inline first children in v4 (`:where()` specificity) — use explicit `mt-*` on block inputs. **Session-39 semantics note:** v4's `space-y-*` puts the space on `margin-block-end` of NON-LAST children (v3 used `margin-top` on non-first) — rhythm pins must assert `margin-bottom` on the earlier child, and porting a v3 layout by margin classes will double-space. Verified live before the PDP/products/contact rhythm pins.
5. **`backdrop-filter` creates a containing block for `position: fixed` descendants.** The sticky header is a glass surface (`backdrop-blur-xl` since session-36), so the mobile menu MUST be portaled to `<body>` (`createPortal` in `Header`). Nesting a fixed drawer inside the header confines it to the header box — the original v1 bug.
6. v4 renames blur/rounded/shadow scales (`blur-sm` is 8px, not v3's 4px). When porting reference values, measure computed styles, do not eyeball. **Live instance (session-34):** the reference's `rounded-xl` computes 0.75rem=12px (v3-era scale), while this build's v4 `--radius-xl` is 1.25rem=20px — a one-notch shift. Fixed with explicit `rounded-[12px]` on the header brand mark (same doctrine as `rounded-[9999px]` on the panel).
7. The mobile project in Playwright pins `browserName: "chromium"` on the iPhone 14 profile — WebKit needs host libs most CI images lack.
8. **v4 computed values differ from v3-era references even when the class name matches.** `/NN` opacity modifiers color-mix in oklab (`bg-card/80` computes to `oklab(... / 0.8)`, not the reference's `rgba(255,255,255,0.8)`) and `rounded-full` computes to `calc(infinity * 1px)` (≈`3.35544e+07px`), not v3's `9999px`. Where a parity pin asserts an exact computed string: bake the alpha into a token (`--color-panel`, `--color-border-soft`, `--color-hero-body`, `--color-quick-add`, `--color-primary-film`, `--color-primary-faint`, `--color-secondary-hover`, `--color-gallery`, `--color-cod-*`) and use `rounded-[9999px]`. Found matching the reference's menu panel (session 4). **Session-36:** the panel BODY itself went solid `bg-card` — the white/80 translucent surface belongs to the HEADER row (`bg-panel` + `backdrop-blur-xl` 24px + `border-border-soft`), all pinned. **Session-38 instances:** the reference's card `bg-card/90` (quick-add) and FB disc `bg-primary/10` both compute sRGB rgba on the v3-era reference — alpha-baked tokens reproduce them exactly. **Session-39 instances:** the PDP gallery tile's `bg-muted/30` computes `rgba(242,240,237,0.3)` on the reference → alpha-baked `--color-gallery`; and `rounded-full` bit a THIRD time (tag pills, stepper container, /products search pill — all now explicit `rounded-[9999px]` because the pins assert the 9999px string).
9. **v4 wraps every `hover:*` utility in `@media (hover: hover)`** — the v3-era reference applies hover styles unconditionally, so in no-hover contexts (mobile emulation) the clone's hovers silently never fired. Fixed globally with `@custom-variant hover (&:hover);` in `src/index.css` (verified by a scratch build: the rules emit un-gated). Pinned by the mobile-project trigger-hover spec. **Measurement corollary:** a click leaves the pointer on the element — move the mouse away before asserting RESTING styles, or the hover treatment bleeds into the reading (bit this session's bare-icon pin and the sweep itself).
10. **The radius/blur/shadow scale keeps shifting one notch (T-6 live instances).** The reference's `rounded-2xl` computes 16px (v3) — this build's v4 `--radius-2xl` is 24px, so 16px surfaces (product cards, category tiles, FB cards, discs) use `rounded-[16px]`; its `rounded-xl` computes 12px (FB discs → `rounded-[12px]`). Its `backdrop-blur-sm` is 4px (quick-add → `backdrop-blur-[4px]`, v4's blur-sm is 8px). Its `shadow-md`/`shadow-xl` geometries are pinned as `--shadow-md`/`--shadow-xl` tokens (v4's defaults are one notch heavier).
11. **Shadow SERIALIZATION differs across engines even when the geometry matches.** The v3-era reference composes box-shadow with 2 leading transparent layers; this build's v4 composes 4 (`--tw-inset-shadow`/`--tw-inset-ring-shadow` add two more). An exact-string `toHaveCSS("box-shadow", …)` pin can therefore NEVER match across the two engines — pin the v3 GEOMETRY via `evaluate` + `toContain(…)` instead (found matching the success-page 36px pills, session 42; the same doctrine as the token-pinned `--shadow-md`/`--shadow-xl` geometries).

## Testing quirks

- **Two-layer split.** Vitest matches `*.test.ts` only (node env, `src/**` + `tests/**` co-located seams); Playwright matches `tests/e2e/*.spec.ts`. No double pickup.
- **E2E runs against the production build.** `npm run build` before `npm run e2e`; the config boots `vite preview` on :4173 (`--strictPort`) and reuses an already-running server locally.
- **Each test gets a fresh browser context**, i.e. fresh localStorage — tests never share cart/session state. Login through the real UI per test (no rate limiter exists, so per-test logins are fine here).
- **`getByRole` name matching is substring by default.** "Close menu" also matches "Close menu overlay" — use `{ exact: true }` (this bit the mobile-nav spec once).
- **The mobile menu is a modal dialog** (`role="dialog" aria-modal="true" aria-label="Site menu"`) with a focus trap: focus enters at the search pill (or the input once expanded), Tab cycles among the panel's 7 focusables (search control + 6 links), Escape restores focus to the trigger. The inner `<nav aria-label="Mobile">` keeps its landmark role — specs may keep using it. The panel body is SOLID `bg-card` (session-36 pixel-verified; the session-4 white/80 reading had measured the reference's translucent HEADER row, not the panel body) with a `border-border-soft` bottom hairline; it does NOT dim the page and has no shadow (re-measure before "fixing"). ## Conventions

- TypeScript strict; no `any` (`unknown` at boundaries); no `ts-ignore`. Unused locals/params are compile errors — prune imports.
- Components: named-function exports, one domain per file (`chrome.tsx` = shared chrome, `product.tsx` = card primitives). Pages are kebab-cased files with PascalCase exports.
- Assets live in `public/images/` and are referenced by absolute path (`/images/...`). Product images are PNG; the catalog in `src/data/catalog.ts` is the seed (reference-parity products keep exact names/prices/ratings).
- **Versioned storage key**: bump `STORAGE_KEY` (`src/lib/storage-key.ts`) whenever `PersistedState` shape or the seed catalog changes — stale client data otherwise shadows the new catalog (this bit the redesign). The bump is *enforced*: `tests/catalog-hash.test.ts` sha-256-pins `src/data/catalog.ts` to a key via `tests/catalog-registry.json`; a seed edit without the bump (and a registry row for the new hash) fails the gate with repair instructions.
- Conventional Commits; docs (`AGENTS.md`, `CLAUDE.md`, `README.md`, `Project_Architecture_Document.md`) are updated in the same commit as the change they describe.
- Never commit: `.env`, `db/*.db`, `node_modules/`, `dist/`, `test-results/`, `playwright-report/`, `tests/e2e/.auth/`.
- The trap log above grows (documented) instead of being worked around.
